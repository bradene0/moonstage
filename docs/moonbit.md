# MoonBit for Moonstage behaviors

A primer for writing behaviors, aimed at agents and developers new to [MoonBit](https://www.moonbitlang.com).
Every snippet here compiles with the toolchain CI uses. You need very little of the language: behaviors
are small functions that read and write numbers through `@sdk`.

## Layout

```text
behaviors/
├── moon.mod                      name = "<game>/behaviors", imports moonstage/sdk
└── <name>/                       one package per behavior module in moonstage.json
    ├── moon.pkg                  imports + the four wasm exports (copy from an existing behavior)
    ├── <name>.mbt                your code
    └── slots.generated.mbt       generated by `moonstage build` — never edit
```

`moon.pkg` for a behavior that uses math:

```text
import {
  "moonstage/sdk",
  "moonbitlang/core/math",
}

options(
  link: {
    "wasm": {
      "exports": [ "ms_abi_version", "ms_start", "ms_update", "ms_event" ],
    },
  },
)
```

Leave out the `math` line if you don't use `@math` (it is a warning, not an error).

## The four entry points

```moonbit
///|
pub fn ms_abi_version() -> Int32 {
  @sdk.abi_version
}

///|
pub fn ms_start(entity : Int32) -> Unit {
  @sdk.set_state(entity, state_count, 0.0)
}

///|
pub fn ms_update(entity : Int32, dt : Double) -> Unit {
  ...
}

///|
pub fn ms_event(entity : Int32, event : Int32, source : Int32, value : Double) -> Unit {
  if event == event_hit && source == entity {
    ...
  }
}
```

- All four must exist. Use `()` as the body of one you don't need, and prefix unused parameters with `_`.
- **Never name a parameter `self`** — that declares a method and fails with error 4059. Use `entity`.
- Separate top-level items with a `///|` line (the formatter expects it).

## The language you need

```moonbit
let speed = @sdk.param(param_speed)          // immutable
let mut vx = @sdk.state(entity, state_vx)    // mutable
vx = vx + 10.0 * dt                          // assignment needs `let mut` (else error 4087)

let count = @sdk.state(entity, state_count).to_int()   // Double -> Int
let offset = count.to_double() * 10.0                  // Int -> Double (no implicit conversion: error 4014)

let label = if count == 2 { 1.0 } else { 0.0 }         // if is an expression
if !@sdk.exists(target) {
  return                                               // early return
}
for i = 0; i < 3; i = i + 1 {
  ...
}
while n < 2 {
  n = n + 1
}

let dist = (dx * dx + dy * dy).sqrt()                  // methods on Double: sqrt, abs, floor, ...
let angle = @math.atan2(dy, dx)                        // trig is not a method: @math.sin(x), @math.cos(x),
                                                       // @math.pow (needs the math import in moon.pkg)
let near = dist < 20.0 && @sdk.is_active(target)       // && || !

@sdk.spawn_at(prefab_bullet, x, y) |> ignore           // discard a return value (else error 4014)
```

Helper functions:

```moonbit
///|
fn approach(value : Double, target : Double, step : Double) -> Double {
  if value < target {
    @sdk.clamp(value + step, value, target)
  } else {
    @sdk.clamp(value - step, target, value)
  }
}
```

## Slots

Never write slot numbers. Declare names in the behavior's entry in `moonstage.json` and use the generated
constants: `params: ["speed"]` → `param_speed`, `state: ["vx"]` → `state_vx`, and likewise `ref_`, `input_`,
`event_`, `prefab_`, `scene_`, `sound_`, `save_`, `tag_`. camelCase becomes snake_case (`turnSpeed` → `param_turn_speed`).
An unknown name is error 4021 — add it to `moonstage.json` and rebuild.

State slots are names, not per-module storage. To read or write another entity's state, list that name
in your own behavior's `state` too: if a `player` behavior declares `state: ["score"]` and a `hud`
behavior also declares `state: ["score"]`, then `@sdk.state(@sdk.ref_entity(ref_player), state_score)` in
`hud` reads the player's score. A state value nobody has set reads as 0.

A scene or test can give an entity starting state (`"behavior": { "module": "ship", "state": { "shield": 1 } }`
or a `setup` operation). `ms_start` runs after that and overwrites anything it sets, so initialise state in
`ms_start` only when it is still 0 if you want scenes and tests to be able to override it.

Events go to every entity whose behavior module declares that event in its `events` list, not only to the
entity that emitted it. `source` tells you who emitted it; ignore events that are not about you.

## What to keep where

- Per-entity data lives in **state** (`@sdk.state` / `@sdk.set_state`), not in MoonBit globals: one module
  instance is shared by every entity that uses it.
- Randomness only from `@sdk.random()` / `@sdk.random_range(lo, hi)`, so runs are reproducible.
- Coordinates are pixels with y down; rotation is radians, clockwise.

## The SDK at a glance

Every function is `@sdk.<name>`. Entities are `Int32` handles; slots are generated constants.

| Function | Does |
| --- | --- |
| `x(e)`, `y(e)`, `rotation(e)`, `scale_x(e)`, `scale_y(e)` | Read the transform (relative to the parent) |
| `set_x(e, v)`, `set_y(e, v)`, `set_position(e, x, y)`, `set_rotation(e, r)`, `set_scale(e, sx, sy)` | Write it |
| `state(e, state_x)`, `set_state(e, state_x, v)` | Per-entity numbers, on any entity |
| `param(param_x)` | This entity's parameter |
| `ref_entity(ref_x)` | Handle of a referenced entity, or `no_entity` (-1) |
| `input(input_x)` | Axis -1..1 or button 0/1 |
| `emit(event_x, value)` | Send an event; this entity is the source |
| `random()`, `random_range(lo, hi)` | Seeded randomness |
| `time()` | Simulation seconds since the scene started |
| `is_active(e)`, `set_active(e, Bool)` | Hide/show (and pause) an entity and its children |
| `spawn(prefab_x)`, `spawn_at(prefab_x, x, y)` | New entity from a prefab; returns its handle |
| `remove(e)`, `exists(e)` | Remove at end of tick; check a handle is still live |
| `is_prefab(e, prefab_x)` | Was `e` spawned from that prefab (e.g. what did I collide with?) |
| `count_tagged(tag_x)` | How many live entities have that tag (e.g. blocks left, enemies alive) |
| `nth_tagged(tag_x, n)` | The n-th tagged entity, for `n` from 0 below the count, or `no_entity` |
| `nearest_tagged(tag_x, e)` | The tagged entity closest to `e` (not `e` itself), or `no_entity` |
| `tile_solid(x, y)` | Is there a solid tilemap tile at this world point (check before moving there) |
| `load_scene(scene_x)` | Switch scenes at the end of the tick |
| `play_sound(sound_x, volume)` | Play an audio asset |
| `load_save(save_x)`, `store_save(save_x, v)` | Numbers that survive reloads (and scene switches) |
| `distance(a, b)`, `clamp(v, lo, hi)`, `log(v)` | Helpers |
| `abi_version`, `no_entity` | Constants |

Scene switches rebuild every entity, so carry values such as a final score to the next scene with
`store_save` / `load_save`.

The full SDK is `packages/moonbit-sdk/sdk.mbt`; the raw WebAssembly imports are in `moonstage guide behavior-abi`.

## Compiler errors you will see

`moonstage build` reports them as `MS3006` with the file and `line:col`, plus a hint for these:

| Code | Usually means | Fix |
| --- | --- | --- |
| 4059 | A parameter is named `self` | Rename it `entity` |
| 4021 | Unbound identifier | A slot name not in `moonstage.json` (add it, rebuild), or `Math.x` instead of `@math.x` (import `moonbitlang/core/math`) |
| 4014 | Type mismatch | `.to_double()` / `.to_int()`, or `\|> ignore` an unused result |
| 4087 | Assigning to an immutable variable | Declare it with `let mut` |
