# Eval run 2026-10-30: Moonstage vs freestyle

Four fresh agents (same model, no knowledge of Moonstage beyond the CLI path) built the two briefs in
`evals/briefs.json`, once with Moonstage and once as a single freestyle HTML file, then applied each brief's
follow-up request. Moonstage was at commit `e7fe3f2` (unreleased; includes `moonstage guide`, templates,
`@moonstage/physics`, saves and single-file builds).

## Reading it honestly

**Freestyle won on speed and size.** Both freestyle agents finished with about half the tool calls, half the
time and a third fewer tokens, and their follow-up edits were tiny. The freestyle tower agent even wrote its
own rigid-body engine, and its tower stood stably by default.

**Moonstage won on verifiability and structure.** Both Moonstage agents left regression tests (7 and 9) that
run headlessly, every project validates, the best score persists through the platform rather than hand-rolled
localStorage, and each game builds to a single file without extra work. The freestyle agents verified with
ad-hoc scripts (the tower agent wrote a 530-line Node harness that isn't part of the game).

**The edit-size gap is mostly format, not logic.** The Moonstage tower's follow-up was 1,255 lines of new
level-2 scene JSON (generated by the agent's own script; pretty-printed JSON puts every number on its own
line) and about 80 lines of behavior and test changes. The dodger follow-up was similar. A more compact scene
representation or prefab placement would close most of this gap.

So, for this run: **Moonstage did not yet make agents faster or cheaper. It made their output testable,
structured and portable.** That is a real advantage for iteration over time, but these one-shot briefs don't
reward it, and the friction below cost the Moonstage agents most of their extra calls.

## Friction the Moonstage agents hit (fix list)

1. **Physics stacks crept and collapsed with default solver settings** (10-block tower fell within 60 s
   untouched). The agent raised `substeps`/`iterations` after finding them in the plugin source. Needs warm
   starting and/or sleeping in the engine, better defaults, and the config documented in `guide physics`.
2. **Silent clash with physics-owned state.** An asteroid kept its speed in state `vy`; the physics plugin owns
   `vx`/`vy`/`av` and overwrote it. Validation should warn when a behavior on a physics body uses those names
   for something else.
3. **Docs naming gap.** `docs/behavior-abi.md` names the import `entity_set_active`; the SDK function is
   `@sdk.set_active`. The MoonBit primer needs a table of SDK functions.
4. **No scripted input for `run`/`render`.** `--input` holds one value for the whole run, so the tower agent
   wrote deliberately failing tests to read values. Accept a timeline (the test file's `input` format).
5. **`run --json` eventCounts undercounts long runs** (counts come from the 10,000-event log cap). Count all
   events.
6. **No state survives a scene switch** except saves; the dodger agent used a save to carry the score to the
   game-over screen.
7. **Verbose scenes.** Generated pretty-printed JSON makes levels huge; a compact form (or prefabs placed with
   overrides) would help both authoring and diffs.
8. **Single files are ~210 KB** versus 10–22 KB freestyle: the browser loads all of core, including
   validation, schemas, the test runner and conformance code it never uses.
