## Reading it

**Both agents did much more checking, not less work.** Each used `moonstage check` after edits, and each
went further than earlier runs: the dodger agent played the game in a browser and wrote 15 tests; the tower
agent wrote a script that searched for winning shot sequences through headless runs and saved them as
playthrough tests. The tower's 47 minutes went mostly into level design (making every block clearable with
a fixed-power cannon), which the agent itself called a design problem rather than a tool problem.

**Tool calls are no longer a useful effort measure here.** With `check` available, calls went up because
the agents chose to verify more (browser play, frame conversion, search scripts). A fairer comparison needs a
brief with a fixed definition of done, or a cap on verification.

**Installing from packages worked first time** for both agents, including `@moonstage/physics` and MoonBit
compilation.

## Friction (fixed after this run unless noted)

1. **Slightly bouncy blocks toppled** (`restitution: 0.05`; a 4-block column fell within 45 s). Resting
   contacts were still allowed to bounce. Fixed: only new contacts bounce.
2. **`check` repeated "slots out of date" (`MS3008`)** right after regenerating them. Fixed.
3. **`moonstage run` served stale builds** after edits. Fixed: it rebuilds on page reload.
4. **`--setup` with a test file ignored the test's `saves`.** Fixed.
5. **Primer gaps:** trig is `@math.sin` (not a method), `ms_start` overwrites starting state from scenes and
   tests, and events reach every module that declares them. Documented.
6. **Rendered frames are SVG only**; both agents struggled to view them (ImageMagick fonts, cropping) and
   fell back to a browser. Not fixed: a PNG option needs a rasterizer.
7. **No way to count entities from a behavior** (the tower needed one ref per block). Not fixed: needs a new
   host function (behavior ABI change).
8. **Template `AGENTS.md` goes stale** once the game changes. Not fixed.
